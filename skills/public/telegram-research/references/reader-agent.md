# Подагент: читатель куска выборки

Задание: исходный вопрос пользователя, папка исследования, кусок
`--offset START --end END`.

Ты читаешь свой кусок `messages_filtered.json` целиком и пишешь заметки.
Отчёт не пишешь, по ним его напишут авторы вертикалей.

```bash
V=/mnt/skills/public/telegram-research/scripts
cat verticals.md                                  # вертикали: NAME | вопрос
python3 $V/read.py --offset START --end END       # первая страница твоего куска
python3 $V/read.py --offset N --end END           # N — из строки «next page» внизу
```

Страница сама укладывается в лимит вывода. Листай, пока внизу не будет
`range up to END read to the end`. Не меняй границы куска и не пропускай
страниц: другие куски читают другие подагенты.

## Заметки

Для каждого сообщения, которое что-то говорит по одной из вертикалей, пиши
строку в `notes/START.md`:

```
NAME | что сказано по сути, с цифрами и условиями как в сообщении; кто пишет (агентство, модель, работник, посредник); ×копий, если больше 1 | message_url
```

- Одно сообщение про несколько вертикалей — несколько строк, по одной на
  вертикаль.
- Цифры переписывай точно: ставки, доли, суммы, сроки, страны, площадки. По ним
  авторы будут считать распределения.
- Одна строка — одно сообщение, без пересказа соседних.
- Пропускай сообщения, где ничего нет по вертикалям: чистую рекламу без
  условий, приветствия, флуд.
- Полезное, что не подходит ни к одной вертикали, пиши с `NAME` = `other`.
- Телефоны, @ники и личные страницы людей не переписывай, хватит ссылки.

Пиши файл по ходу чтения, дописывая после каждой страницы, а не в конце. Когда
кусок прочитан до конца, последней строкой добавь `# done START-END`. Без неё
кусок считается непрочитанным. Верни одну строку: сколько сообщений прочитано и
сколько заметок по каждой вертикали.
