# Jev: типизированная оценка уже собранных данных

Используй Jev как вспомогательную эвристику для больших выдач: `noul` — тематическая релевантность, `choice` — наблюдаемая роль ресурса, `score` — приоритет дальнейшего чтения. Критерии задаёшь по вопросу пользователя. Jev не ищет источники, не проверяет факты и не генерирует свободный текст. Не отправляй запрещённые персональные или интимные данные.

Подготовь отдельный JSON со стабильными строковыми ID; исходные ответы Vox не изменяй:

```json
{
  "items": [
    {"id": "candidate-001", "state": "Синтетическое описание: участники задают технические вопросы и отвечают друг другу."}
  ],
  "questions": {
    "relevant": {"type": "noul", "instructions": "Есть ли признаки профессионального обсуждения между участниками?"},
    "role": {"type": "choice", "criteria": {"peer": "Обсуждение между участниками", "advert": "Реклама", "uncertain": "Данных недостаточно"}},
    "priority": {"type": "score", "criteria": ["Низкий приоритет чтения", "Требует проверки", "Высокий приоритет чтения"]}
  }
}
```

В sandbox ключ не нужен; доступ идёт только через доверенный внутренний Jev bridge. Не меняй сетевые настройки. Python CLI использует стандартную библиотеку, stdout содержит только путь сохранённого JSON. До 50 записей и 16 вопросов на порцию; запрос или batch до 256 KiB. Для больших массивов создай отдельные ограниченные порции с реестром всех ID, включая ошибки.

```bash
python3 /mnt/skills/public/telegram-research/scripts/jev.py evaluate --input /mnt/user-data/workspace/branch/jev-input.json --output /mnt/user-data/workspace/branch/jev-result.json
python3 /mnt/skills/public/telegram-research/scripts/jev.py submit --input /mnt/user-data/workspace/branch/jev-input.json --output /mnt/user-data/workspace/branch/jev-batch.json
python3 /mnt/skills/public/telegram-research/scripts/jev.py collect --input /mnt/user-data/workspace/branch/jev-batch.json --output /mnt/user-data/workspace/branch/jev-batch-results-1.json
```

`evaluate` подходит для небольшой быстрой проверки; для массовой обработки предпочитай `submit` и отдельный `collect`. `collect` не ждёт: проверяй `complete`, статусы всех записей и ошибки; следующую квитанцию сохраняй в новый файл. Batch использует последовательную обработку без разрешения платного массового выполнения. После `submit` сохраняется также `.handle.json`; если проверка ответа прервалась, продолжай по этому handle, а не повторяй POST. При неоднозначном сбое POST не отправляй дубликат вслепую. Ненужный batch можно остановить режимом `cancel` с тем же handle и новым `--output`.

Файлы не перезаписываются; `.request.json` связывает результат с SHA256 входа. Результат содержит все исходные ID, официальные ответы, распределения, confidence и usage либо явную ошибку. Читай компактную производную таблицу, а не весь большой JSON в контекст. Ошибка — не отсутствие релевантных данных. Вероятности и confidence не доказанная калибровка; неоднозначность проверяй по сообщениям. Низкая оценка меняет очередь чтения, но не удаляет кандидата и не заменяет реестр решений. Перед цитированием и выводами читай первоисточник.

## Пример: подагент фильтрует сообщения своей группы

Задача: понять, какие условия подработки обсуждают студенты. Из сохранённых
ответов Vox подагент берёт небольшую порцию сообщений своей группы; `id`
связывает классификацию с исходным `(group_id, message_id)`. Ниже вымышленные
тексты для иллюстрации формата, не доказательства:

```json
{
  "items": [
    {"id": "group-1:17", "state": "После пар беру вечерние смены, но работодатель дважды переносил оплату."},
    {"id": "group-1:18", "state": "Сегодня меняется расписание библиотеки."}
  ],
  "questions": {
    "topic": {"type": "noul", "instructions": "Есть ли фактура об условиях совмещения учёбы и работы?"},
    "kind": {"type": "choice", "criteria": {"experience": "Конкретный личный опыт", "offer": "Объявление о работе", "other": "Другая тема или недостаточно данных"}}
  }
}
```

Сохрани этот массив (с реальными допустимыми текстами вместо примеров) как
`jev-input-001.json` в папке группы и вызови `evaluate` либо `submit`/`collect`
по командам выше. В `results` каждая запись сохраняет `id`; успешный ответ
находится в `response.answers`, неуспех — в `error`.

Для порядка чтения можно сначала выбрать `kind.choice == "experience"`, затем
прочитать соответствующие полные сообщения в исходном Vox JSON. Ошибки и
неоднозначные оценки идут в ручную проверку, а не удаляются. Выборку остальных
классов тоже проверь: полезный факт может оказаться внутри объявления. Порог
оценки выбирай под вопрос и проверяй на прочитанных примерах; универсального
порога релевантности нет. Цитаты, ссылки, новые слова и решение о группе
фиксирует подагент после чтения оригинала, а не по одной оценке Jev.
