# Общий реестр исследования

Основной агент и все подагенты используют один абсолютный путь к `registry.json`
в папке исследования. Реестр — учёт работы, а не исследовательский алгоритм:
релевантность, ключевые слова, назначения, полноту карты и текст поручений
определяет центральный агент. Каждая найденная тематическая группа должна
попасть в `groups.todo` и получить исследование; нерелевантные не назначаются. Все изменения делай через `scripts/research_registry.py` или его Python
API `Registry`; не перезаписывай JSON вручную из устаревшего снимка.

Структура версии 1:

```json
{
  "version": 1,
  "groups": {
    "todo": [
      {
        "id": -1001234567890,
        "sources": [{"source": "breadth", "evidence": "/absolute/search.json: message 17", "reason": "Прочитанное сообщение соответствует вопросу"}],
        "assignment": {"owner": "depth-123", "folder": "/absolute/research/groups/123", "claimed_at": "2026-10-12T10:00:00+00:00"}
      }
    ],
    "done": []
  },
  "keywords": {
    "todo": [
      {"key": "подработка", "text": "подработка", "sources": [{"source": "depth-123", "evidence": "https://t.me/example/17", "reason": "Новая формулировка участников"}]}
    ],
    "done": []
  }
}
```

`assignment` появляется только после успешного claim. Уже назначенная группа
остаётся в `groups.todo`; это сохраняет две запрошенные очереди без третьего
списка. Группа в `done` содержит `folder`, `result` (путь к фактическому `.md`),
`owner`, `assessment` (`researched` или `excluded`) и `completed_at`, а также
сохраняет `sources` и предыдущие `attempts`. `remaining_todo` может ссылаться на заметки вне текущего вопроса. Новые
тематические группы и важные для карты переходы нельзя списывать туда как
необязательные: группы добавляются в `groups.todo`, остальные находки
передаются основному агенту для продолжения.
Незавершённая порученная работа — `todo`, а не `done` с оговоркой.

У ключевого слова в `done` есть `search_evidence` — существующий непустой файл
с результатом поиска/журналом проверки — и `completed_at`. Поисковый manifest
с `paused`, `partial`, `error`, `running`, `unresolved`, `traversal_complete=false`
или `stop_reason=timeout` не принимается как завершённый. Основной агент сам
проверяет реальный результат и покрытие запроса; существование файла этого не
доказывает. Ошибка запроса не превращает ключевое слово в выполненное.

## Команды

В примерах `$REGISTRY` — **одинаковый абсолютный путь для всех агентов**;
`$CLI` — путь к `scripts/research_registry.py` этого скилла.

```bash
python3 "$CLI" --registry "$REGISTRY" init
python3 "$CLI" --registry "$REGISTRY" add-keyword "подработка" \
  --source breadth --evidence "Начальная гипотеза по задаче пользователя" \
  --reason "Предполагаемая формулировка аудитории"
python3 "$CLI" --registry "$REGISTRY" complete-keyword "подработка" \
  --evidence /absolute/research/search/manifest.json
python3 "$CLI" --registry "$REGISTRY" add-group -1001234567890 \
  --source depth-123 --evidence "https://t.me/example/17; /absolute/group-card.json" \
  --reason "Проверенный публичный чат; прочитанное сообщение соответствует теме"
python3 "$CLI" --registry "$REGISTRY" claim-group -1001234567890 \
  --owner depth-456 --folder /absolute/research/groups/456
```

Сначала claim, затем запуск подагента. При конфликте claim **не запускай второй
экземпляр**: перечитай реестр. Имя владельца должно однозначно обозначать это
назначение. Если запуск не состоялся или агент остановился с незавершённой
работой, освободи назначение явно и передай следующему агенту папку попытки:

```bash
python3 "$CLI" --registry "$REGISTRY" release-group -1001234567890 \
  --owner depth-456 --status partial --reason "Сохранён прогресс; осталось проверить участника"
```

`release-group` сохраняет владельца, папку и причину в `attempts`; ошибок или
частичного результата в `done` не будет. Назначения не истекают автоматически:
проверь, что прежний агент остановлен, перед освобождением и повторным запуском.

Подагент сохраняет `facts.md`: до одной страницы, для машинной проверки — не
более **500 слов**, только существенная фактура и ссылки на сообщения. Подробные
исходные ответы остаются отдельными файлами. Новые слова и уверенно тематические
группы добавляет через `add-*`; существующие записи сохранят дополнительные
источники, но не появятся в очереди повторно. В `findings.json` при необходимости
можно сохранить внешние ссылки и публичные деловые контакты с источниками,
ролью и причиной релевантности; не собирай личные контакты частных участников.

```bash
python3 "$CLI" --registry "$REGISTRY" complete-group -1001234567890 \
  --owner depth-456 --result /absolute/research/groups/456/facts.md
python3 "$CLI" --registry "$REGISTRY" show
```

`complete-group` проверяет владельца, существование `.md` внутри назначенной
папки, объём и наличие URL источника. Это проверка передачи результата, не
автоматическая приёмка фактов. Для проверенного исключения (например, закрытая
группа) сохрани короткую причину и ссылку на файл карточки в `facts.md`, используй
`--assessment excluded`; публичную ссылку выдумывать не нужно. Недоступная
перспективная группа с незавершённой проверкой остаётся `todo`.

## Программные назначения

Основной агент может импортировать helper, прочитать очередь и сформировать
manifest поручений для массового запуска. Он сам составляет `description` и
`prompt`; helper не вызывает Vox, модели или механизм делегирования.

```python
import sys
sys.path.insert(0, "/mnt/skills/public/telegram-research/scripts")
from research_registry import Registry, RegistryError

registry = Registry("/mnt/user-data/workspace/research/registry.json")
items = []
for group in registry.snapshot()["groups"]["todo"]:
    if "assignment" in group:
        continue
    gid = group["id"]
    owner = f"depth-{gid}"
    folder = f"/mnt/user-data/workspace/research/groups/{gid}"
    # choose_prompt(group) — собственное поручение основного агента,
    # с исходной задачей, критериями, путями и этим конкретным group ID.
    prompt = choose_prompt(group)
    try:
        registry.claim_group(gid, owner=owner, folder=folder)
    except RegistryError:
        continue  # Другой диспетчер уже назначил группу; перечитай при необходимости.
    items.append({"key": str(gid), "prompt": prompt})
# Сохрани items и передай доступному пакетному инструменту делегирования.
# При отказе запуска освободи только соответствующие незапущенные назначения.
```

Для редкого связанного конгломерата основной агент явно объясняет исключение,
резервирует каждый ID и направляет в общую папку одного подагента; завершение
учитывается отдельно для каждого ID. Скрипт сам группы не объединяет.

## Параллельная запись

POSIX `flock` на постоянном соседнем файле `registry.json.lock` защищает весь
цикл чтение–изменение–запись. Новый JSON записывается во временный файл в той же
папке, синхронизируется `fsync`, затем атомарно заменяет старый; каталог также
синхронизируется. Чтение через API использует ту же блокировку. Все агенты
должны видеть один общий диск, JSON и lock; не удаляй lock во время работы.

ID групп дедуплицируются как целые числа, слова — по Unicode NFKC, casefold и
нормализации пробелов. Дедупликация действует одновременно по `todo` и `done`;
синонимы не склеиваются. Все различные `source/evidence/reason` сохраняются.
Повреждённый JSON/схема вызывает ошибку и не перезаписывается, даже через `init`.
`init` существующего корректного файла ничего не обнуляет. Для нового
исследования используй новый путь.
